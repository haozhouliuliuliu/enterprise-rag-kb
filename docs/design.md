# 方案设计说明

本文记录第一版的设计取舍，供第二步部署和第三步验收对照。

## 1. 范围

单台企业内部 Windows 电脑，Docker Desktop 本地运行 RAGFlow；员工通过浏览器上传 PDF/Word 并提问；回答必须带可核对的 chunk 级引用。不接云服务器、不跑本地大模型。

## 2. 组件与职责

| 组件 | 职责 | 是否自建 |
| --- | --- | --- |
| RAGFlow | 文档管理、解析、切片、检索、对话、引用展示 | 否（官方镜像） |
| DeepDoc | PDF/Word 版面分析、表格/OCR 解析 | 否（RAGFlow 内置） |
| Elasticsearch 8.11.3 | chunk 向量与全文索引 | 否（compose 自带） |
| MySQL 8.0.40 | 用户、知识库、文档、会话等元数据 | 否（compose 自带） |
| MinIO（silo） | 原始文件对象存储 | 否（compose 自带） |
| Valkey 8 | 缓存/队列 | 否（compose 自带） |
| 阿里云百炼 | 对话生成 + 文本向量化 | 否（在线 API） |

## 3. 关键决策

### ADR-001：选用 RAGFlow，不选用 Dify

- **背景**：需要在“文档解析质量”和“引用可追溯”之间取得平衡，且只允许运行一套应用。
- **决策**：只部署 RAGFlow v0.27.2。
- **理由**：
  - RAGFlow 的回答自带 chunk 级引用，引用可展开到原始片段；
  - DeepDoc 对表格、扫描件、复杂版面的处理更符合说明书/检验规范；
  - 官方 compose 一体化交付，部署面小；
  - Apache-2.0，适合企业内部。
- **代价**：RAGFlow 的工作流/Agent 编排能力不如 Dify 灵活；第一版不需要复杂编排，可接受。
- **复审条件**：若后续需要多步骤工具调用、审批流或对外 API 编排，再评估 Dify 或独立编排层。

### ADR-002：向量库复用 RAGFlow 集成组件

- **决策**：使用 compose 默认的 Elasticsearch 8.11.3，不单独部署向量库。
- **理由**：版本兼容由 RAGFlow 保证；少一套服务就少一份内存/磁盘开销；本机资源紧张。
- **代价**：Elasticsearch 内存占用较高；若资源不足可在第二步评估切换 Infinity（compose 已提供 profile）。
- **复审条件**：导入真实规模数据后，若检索延迟或内存不可接受，再切换 `DOC_ENGINE`。

### ADR-003：在线模型只用一家供应商

- **决策**：对话 `qwen-plus` + Embedding `text-embedding-v4`，均来自阿里云百炼，共用 `DASHSCOPE_API_KEY`。
- **理由**：一把 key、一个计费口径、RAGFlow 原生支持；中文资料效果好；无需本地 GPU。
- **代价**：依赖公网与供应商可用性；数据会发送到在线模型服务，因此只使用虚构资料演示。
- **复审条件**：企业要求数据不出内网时，改为本地 embedding + 本地 LLM（超出第一版范围）。

### ADR-004：第一版不做 Rerank 与复杂检索调优

- **决策**：先用 RAGFlow 默认检索参数跑通引用闭环，不额外引入 rerank 服务。
- **理由**：第一版目标是验证“能查到、答得出、引得到”，不是追求最优召回。
- **复审条件**：测试集出现“答非所问”或“引用不相关”时，再启用百炼 rerank 或调整 chunk 大小/相似度阈值。

## 4. 引用链路与验收口径

1. 文档上传后保存原文（MinIO）并解析为 chunk。
2. chunk 写入 Elasticsearch，元数据（文档、位置）写入 MySQL。
3. 提问召回 top-k chunk，作为上下文提交给对话模型。
4. 模型输出引用编号，RAGFlow 渲染引用列表。
5. 验收时逐条检查：回答中的事实是否能在引用片段中找到；引用是否能定位到文件与片段。

**不通过的情形**：只有文件名没有片段；引用片段与结论无关；模型编造数值但引用中不存在。

## 5. 数据设计

三类虚构资料，覆盖不同解析难点：

| 资料 | 解析难点 | 测试价值 |
| --- | --- | --- |
| 产品说明书（PDF） | 多级标题、参数表、图示 | 单文档事实、参数查询 |
| 质量检验规范（Word） | 表格、数值公差、抽样规则 | 精确数值、边界条件 |
| 设备操作手册（PDF） | 步骤编号、安全警告 | 流程问答、跨段落整合 |

## 6. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 磁盘不足（C 盘约 16 GB） | 镜像拉取/索引失败 | 把 Docker 磁盘镜像迁到 D 盘或清理 C 盘，见 known-issues |
| 内存 15.3 GB，Docker VM 仅 8 GB | 容器 OOM、ES 启动失败 | 调整 `.wslconfig` 内存上限，降低 `MEM_LIMIT` |
| 在线模型限流/欠费 | 问答失败 | 预先充值、设置重试与错误提示；演示前预热 |
| 扫描版 PDF 解析差 | 引用缺失 | 优先使用文本型 PDF；必要时启用 OCR |
| 引用粒度与页码不一致 | 验收争议 | 以 chunk 片段为验收单位，页码仅作辅助 |

## 7. 后续演进

- 引入 rerank 与查询改写，提升召回质量；
