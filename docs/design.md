# 设计说明

## 设计目标

验证企业文档问答中三个关键环节：检索是否找到正确依据、回答是否提供可核对来源、资料不足时是否拒绝编造。

## 技术选择

| 层次 | 选择 | 职责 |
| --- | --- | --- |
| RAG 应用 | AnythingLLM Desktop | 工作区、文档管理、检索编排与引用展示 |
| 文档 | PDF / DOCX 等办公文件 | 虚构产品、质量、设备及流程资料 |
| 本地存储 | 应用内置 SQLite / LanceDB | 工作区元数据与检索索引 |
| 生成模型 | 阿里云百炼 qwen-plus | 根据检索片段生成回答 |
| 向量模型 | 阿里云百炼 text-embedding-v4 | 将文档片段与问题向量化 |
| 评测 | Python + Developer API | 固定题集、检索来源与回答判定 |

## 设计原则

1. **先检索再回答**：回答以实际检索到的片段为上下文。
2. **引用可核对**：评测不仅检查回答文本，也检查来源能否支持结论。
3. **无依据时拒答**：无答案题要求系统明确说明资料不足。
4. **固定题集**：使用可重复执行的问题与判定规则，减少仅凭主观观感评价。
5. **明确数据边界**：示例资料保持虚构，外部模型调用的数据流在安全说明中公开。

## 适用范围

该设计用于单机 RAG 方案验证与技术选型参考。它不等同于自研检索引擎，也不具备企业级身份权限、数据隔离、生产审计和高可用能力。
