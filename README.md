# 企业知识库 RAG 验证

> 用现成 RAG 应用 + 在线模型，验证企业文档能否被正确检索、回答能否给出可核对来源，以及资料不足时能否拒绝编造。

## 业务场景

企业制度、产品手册、检验规范通常散落在 PDF、Word 里。新员工或业务人员遇到问题时，往往靠问人、翻目录、搜关键词，既慢又难确认依据。

这个项目用一套**完全虚构**的企业资料，搭建一个可重复验证的知识库问答流程：

1. 导入产品说明书、检验规范、设备手册等文档；
2. 员工用自然语言提问；
3. 系统检索相关片段，生成回答并标出引用来源；
4. 用固定 30 题检查检索命中、来源支持与无答案拒答。

它适合作为企业知识库/RAG 的选型验证模板，也可用于向业务部门演示“回答从哪里来、什么时候应该拒答”。

## 技术方案

| 层 | 选择 |
|---|---|
| RAG 应用 | AnythingLLM Desktop |
| 文档 | PDF、DOCX 等办公文件 |
| 检索与存储 | 应用内置 SQLite / LanceDB |
| 回答模型 | 阿里云百炼 `qwen-plus` |
| 向量模型 | 阿里云百炼 `text-embedding-v4` |
| 评测 | Python 脚本调用 Developer API，记录 Top-5 来源、回答与判定 |

本项目重点是**集成、评测和引用验证**，不把 AnythingLLM 描述为自研检索引擎。

## 验证结果

固定评测共 30 题，其中 25 题有答案、5 题无答案：

| 指标 | 结果 |
|---|---:|
| Top-5 检索命中 | 21/25（84%） |
| 最终答案来源支持 | 22/25（88%） |
| 无答案正确拒答 | 5/5（100%） |
| 评测语料 | 22 份虚构文档 |

完整判定口径见 [tests/results/full-30-summary.md](tests/results/full-30-summary.md)。结果只代表当前虚构语料、题集、应用和模型配置，不代表生产环境准确率。

## 架构

```text
虚构 PDF / DOCX
      │
      ▼
AnythingLLM 解析与切分
      │
      ▼
本机索引（LanceDB / SQLite）
      │
用户问题 ──► 向量化与检索 ──► Top-N 片段 ──► 外部模型生成回答
      │
      ▼
回答 + 来源片段展示
      │
      ▼
Python 固定题集评测（Top-5 / 来源支持 / 拒答）
```

数据流边界：文档管理和检索在本机完成；生成回答时，问题和检索片段会发送到配置的模型服务。仓库只使用虚构数据。

## 可复用产出

- 22 份虚构企业文档与文档清单；
- 30 道固定问题（含 5 道无答案题）与判定规则；
- `tests/eval.py` 评测脚本：记录每次检索来源、回答和判定；
- 部署与安全边界说明，可作为企业内知识库试点的起步材料。

## 运行验证

1. 安装 AnythingLLM Desktop，按官方说明配置模型提供方；
2. 创建工作区，导入 `data/` 下的虚构文档；
3. 在应用设置中启用 Developer API；
4. 复制 `.env.example` 为 `.env`，填入本机 API 地址、工作区标识和 Developer API key（`.env` 已被忽略，不要提交）；
5. 执行：

```bash
python tests/eval.py
```

详细步骤见 [docs/deployment.md](docs/deployment.md)，文档清单见 [docs/README.md](docs/README.md)。

## 已知限制

- 依赖 AnythingLLM 的解析、切分和引用展示能力；
- 表格被切分后，行列关系可能不完整；
- 相似型号、版本对比、跨文档综合问题仍可能漏检；
- 单机验证方案，不提供企业级身份权限、多租户、高可用或生产审计；
- 外部模型调用会把问题和检索文本发送到模型服务，不适用于未获授权的真实机密、客户资料或个人信息。

## 数据与安全

仓库内业务文档、企业名称、产品型号和数值均为虚构。API key 只保存在本机 `.env` 或环境变量中，不进入版本库。详见 [docs/security.md](docs/security.md) 和 [known-issues.md](known-issues.md)。
