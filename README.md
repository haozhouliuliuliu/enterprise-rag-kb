# 企业知识库 RAG 验证项目

基于成熟 RAG 应用搭建的企业文档问答验证方案，重点验证文档入库、检索、答案引用与无答案拒答是否形成可复核的闭环。

## 项目概览

企业制度、产品手册和操作规范通常分散在 PDF、Word 等文件中。此项目使用一组完全虚构的企业文档，建立可重复执行的问答评测，检查系统能否找到正确资料、给出可追溯引用，并在资料不足时拒绝编造。

本项目以集成和评估现成 RAG 应用为重点，**不将 AnythingLLM 本身描述为自研检索引擎**。配套的评测脚本和固定题集用于量化其表现。

## 验证结果

固定评测共 30 题，其中 25 题有答案、5 题为无答案题。

| 指标 | 结果 |
| --- | ---: |
| Top-5 检索命中 | 21/25（84%） |
| 最终答案来源支持 | 22/25（88%） |
| 无答案题正确拒答 | 5/5（100%） |
| 评测语料 | 22 份虚构文档，最终索引 29 个 chunk |

结果表明该方案能够完成基础文档问答和来源核对；跨文档综合推理、相似型号与版本辨别仍有改进空间。完整判定口径见 tests/results/full-30-summary.md。

## 技术方案

- RAG 应用：AnythingLLM Desktop
- 文档：PDF、DOCX 等常见办公文件
- 本地存储与检索：应用内置 SQLite / LanceDB
- 回答模型：阿里云百炼 qwen-plus
- 向量模型：阿里云百炼 text-embedding-v4
- 评测：Python 脚本通过 Developer API 调用并记录检索来源和回答判定

## 架构

1. 导入文档并由应用解析、切分。
2. 文档片段在本机建立索引。
3. 问题进入检索流程，系统返回相关片段。
4. 问题与检索片段发送给配置的模型服务生成回答。
5. 评测脚本对 Top-5 来源、最终引用与拒答表现进行检查。

## 运行验证

1. 安装 AnythingLLM Desktop，并按官方说明配置模型提供方。
2. 创建工作区并导入 data/ 下的虚构文档。
3. 在应用设置中启用 Developer API。
4. 在本机环境变量中设置评测 API 地址、工作区标识和 API key。
5. 安装 Python 运行环境后，执行：

   python tests/eval.py

完整部署说明见 docs/deployment.md；文档列表见 docs/README.md。

## 数据安全边界

仓库内业务文档均为虚构样例。使用百炼模型时，用户问题和检索到的文本片段会发送到外部模型服务，因此此配置不适用于未获授权的真实企业机密、客户资料或个人信息。API key 只应保存在本机配置或环境变量中，不能提交到 Git。

## 已知限制

- 该方案依赖 AnythingLLM 的解析、切分和引用展示能力。
- 表格被切分后，行列关系可能不完整。
- 相似型号、版本对比和多文档综合问题仍可能漏检。
- 该项目为单机验证方案，不提供企业级身份权限、多租户隔离、高可用或生产审计。

项目边界与数据流说明见 docs/security.md。
